
## 一、資料與切分（Chunking）層錯誤

**案例一：Chunk 完整性未經人工驗證**

- 情境：30 個 chunk 全由 LLM 讀取全文後自行切分產生，未有人工比對原文頁碼與範圍。
- 問題（錯誤來源：資料）：chunk_id 本質上是後續所有檢索與生成的隱性標籤（label）——若切分階段就遺漏表格、腳註，或把不同章節層次的內容合併進同一 chunk，後面 20 題無論檢索或生成再嚴謹，都建立在錯誤的資料基礎上，屬於錯誤會被放大而非發現的類型。
- 改善方向：逐一標記對應原文頁碼／段落範圍，並人工抽查 coverage 是否有遺漏或誤合併。

**案例二：圖表文字化程度過淺**

- 情境：圖 1 流程圖僅用 20 字摘要描述（C7 chunk 摘要），表格類 chunk 僅有標題級摘要。
- 問題（錯誤來源：資料）：語意向量表示所依賴的文字密度不足，圖表在檢索階段極易因摘要過短而未被正確命中，或命中後生成階段仍需回頭猜測圖片內容（Q13 已刻意迴避此風險，但屬於個案處理，非系統性解法）。
- 改善方向：圖表類 chunk 需先做結構化文字化，不能僅摘要。

## 二、檢索（Retrieval）層錯誤

**案例三：角色式檢索以摘要判斷取代真正向量檢索**

- 情境：Step B 由 LLM 讀 30 個 chunk 的 20 字摘要後人工判斷相關性，並非 embedding + Top-k + reranking。
- 問題（錯誤來源：檢索）：用LLM摘要會影響RAG檢索效能（因為 LLM 直接讀到「標題語意」而非原始文字的向量相似度）。
- 改善方向：實作真實 embedding（如 OpenAI/BGE embedding + cosine similarity）並用 HNSW 或 brute-force Top-k 比對，觀察與角色式檢索結果的差異。

**案例四：文件層次混淆（Q19）**

- 情境：Step B 對語意含糊的問題（「受試者是誰」）同時選中真實記錄（C1、C7）與 AI 生成論文自述的虛構樣本（C11、C16），直接把 60 人當答案。
- 問題（錯誤來源：檢索）：60 人這個數字確實逐字存在於文件中，不是憑空捏造，但檢索缺失了chrunk的注意力（是本專題的真實記錄，還是 AI 生成內容裡描述的另一個假想實驗），屬於檢索相關性判斷缺乏語境層級（context-level）過濾。
- 改善方向：檢索 prompt 中加入「請標註每個候選 chunk 屬於『研究記錄』或『AI生成產物』」的預先分類，再決定是否採用。

## 三、Prompt 設計層錯誤

**案例五：強制關聯幻覺（Q20，未收斂版）**

- 情境：全文 30 個 chunk 均無 RAG／向量檢索相關內容，但仍輸出「高度相關」「直接參考價值」。
- 問題（錯誤來源：Prompt）：System Prompt C 原始版本沒有明確要求「無依據時該欄位必須省略」。
- 改善方向：拒答規則必須寫成顯式條件句（如「若 30 個 chunk 摘要中無關鍵詞對應，則該欄位輸出『無』，不得進行類比或推論」），非依賴模型自行判斷何時該拒答。

**案例六：grounded QA 與允許推論的任務未在 Prompt 層分流**

- 情境：Q6、Q9 要求模型自行計算兩構面分數差距（gap）並給出「哪個工具最平衡」「該選哪種提示詞」的建議，這已超出「僅根據段落回答」的原始 Prompt 設定。
- 問題（錯誤來源：Prompt）：同一份 System Prompt C 同時被要求「不得使用訓練知識補充」與「回答需要跨 chunk 計算與判斷」的題目，兩種任務對「幻覺」的定義其實不同——前者是禁止臆測事實，後者是允許基於檢索到的數字做二次運算——但 prompt 沒有區分這兩種模式，只能靠模型自主在輸出中加註「衍生計算」字樣，屬於補救而非設計層的解法（呼應老師評語第 4 點）。
- 改善方向：拆成兩個獨立 System Prompt（如 Prompt C-1：純文件抽取；Prompt C-2：允許數值運算但需列出計算式），並在 Step B 檢索階段就先分類問題屬於哪一種。

## 四、模型／生成（Generation）層錯誤

**案例七：生成者與查核者角色由同一模型兼任**

- 情境：Step C（生成）與 Step D（查核）皆由同一顆 LLM 執行，僅靠不同 System Prompt 切換角色。
- 問題（錯誤來源：模型）：同一模型自產自評（self-grading）的結構性風險，不是單題 prompt 沒寫好的問題。
- 改善方向：查核角色至少換用不同模型（如生成用 GPT 系列、查核用 Claude 或開源模型），或加入人工 gold answer 抽查一致性（教師評語第 3 點）。


## 五、評估指標層錯誤

**案例八：缺乏整體量化指標，僅有逐題人工判斷**

- 情境：目前 20 題的正確性、依據性、錯誤類型皆為研究者本人逐題主觀標註（「正確」「有依據」「文件層次混淆」等文字標籤），沒有彙總成 retrieval coverage、faithfulness、拒答準確率（refusal precision/recall）、語境誤用率等數字。
- 問題（錯誤來源：評估指標）：沒有量化指標，就無法回答「Prompt 到底把幻覺率降低了多少」這類問題也無法用於下一輪 Prompt 迭代的客觀比較基準。
- 改善方向：至少建立三個數字：(1) retrieval coverage = 正確命中 chunk 數／應命中 chunk 數，(2) faithfulness rate = Step D 判定「通過驗證」的題數／總題數，(3) 拒答正確率 = 該拒答且正確拒答的題數／應拒答題數（Q14–16 為分母）。

**案例九：正確性判斷缺乏獨立於研究者本人的 Gold Answer 基準**

- 情境：20 題的「預期答案」欄位是本人依原文手動整理，同時也是判斷 AI 回答是否正確的評分者。
- 問題（錯誤來源：評估指標）：出題、訂正答案、評分三者由同一人完成，沒有第三方檢驗，無法排除評分標準本身的系統性偏誤。
- 改善方向：至少找一位第二評分者（同學或用另一顆 LLM 當 judge）獨立對 20 題重新評分一次，計算兩者評分的一致率。
